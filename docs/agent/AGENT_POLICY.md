# MyJARVIS Agent 工具与审批策略

本文件定义 MyJARVIS Agent 可以使用哪些工具、每项工具的风险等级、权限边界、审批方式以及失败恢复规则。

目标不是限制 Agent 的能力，而是保证 Agent 能够行动的同时，不越权、不伪造结果、不绕过用户对关键变化的确认。

## 1. 设计原则

1. **模型只提出结构化意图，后端负责执行真实操作。**
2. **当前用户身份只能从认证上下文获得，不能由 LLM 传入 `user_id`。**
3. **Agent 不能直接访问数据库、密钥、其他用户数据或任意 URL。**
4. **查询、草稿、低风险操作、关键变化和用户专属操作必须分组管理。**
5. **关键计划变化必须由用户批准，Agent 只能创建待审批建议。**
6. **画像洞察和正式画像事实分离，Agent 不能确认自己的推断。**
7. **每个写操作都要校验参数、前置状态、用户权限和幂等性。**
8. **模型、搜索或工具失败不能产生虚假的成功状态。**
9. **所有 Agent 运行和工具调用都要留下可审计记录。**
10. **不确定风险时，按更高风险处理。**

## 2. Agent 与后端的权限边界

### 2.1 Agent 可以做的事情

- 读取当前用户被授权的目标、计划、任务、跟进和已确认画像上下文。
- 生成计划草稿和计划调整建议。
- 根据用户明确反馈追加任务进度记录。
- 执行不改变计划关键约束的低风险调整。
- 创建或修改用户允许的跟进安排。
- 搜索公开资料并返回可验证来源。
- 提出候选画像洞察或待确认画像事实。
- 基于真实执行记录生成复盘草稿。

### 2.2 Agent 不可以做的事情

- 自行激活计划或把草稿版本设为生效版本。
- 自行批准、拒绝或应用关键计划变化。
- 绕过用户确认写入正式画像。
- 把自己推断的性格或敏感属性直接保存为 `ProfileFact`。
- 读取或修改其他用户的数据。
- 直接执行 SQL、任意文件操作或任意网络请求。
- 自行删除用户、目标、计划、会话或画像数据。
- 修改密码、登录方式、权限或安全设置。
- 把用户未明确表达的内容当成任务完成。
- 根据网页中的指令调用高权限工具。

### 2.3 身份注入

所有工具调用都不允许由模型传入 `user_id`。执行器从已认证请求中读取当前用户，再注入工具参数。

工具层必须拒绝以下情况：

- 模型尝试传入 `user_id` 或 `owner_id` 覆盖当前身份。
- 目标、计划、任务或消息属于其他用户。
- 子对象与父对象所属用户不一致。
- 通过伪造 ID 建立跨用户任务依赖或证据关系。

## 3. 工具分类

| 类型 | 示例 | 是否修改业务数据 |
|---|---|---|
| 查询工具 | 读取当前计划、最近跟进、已确认偏好 | 否 |
| 草稿工具 | 创建计划草稿、提出计划变更、生成复盘 | 只产生草稿或待确认记录 |
| 操作工具 | 更新任务进度、安排提醒、执行低风险调整 | 是，必须通过状态和权限校验 |
| 用户专属操作 | 激活计划、批准关键变化、确认画像洞察 | Agent 没有直接调用权限 |

“生成计划草稿”“提出调整建议”“生成画像候选”都属于草稿类操作，不能让对象直接进入生效状态。

## 4. 查询工具

### 4.1 `get_goal_context`

| 项目 | 内容 |
|---|---|
| 功能 | 读取当前用户的一个目标以及关联计划摘要 |
| 风险等级 | `R0` |
| 输入 | `goal_id`、是否包含已完成任务 |
| 前置条件 | 当前用户拥有该目标 |
| 权限 | 只读 |
| 副作用 | 无 |
| 输出 | 目标状态、当前生效计划、当前版本、里程碑和任务摘要 |
| 幂等策略 | 天然幂等 |
| 失败行为 | 目标不存在或不属于当前用户时拒绝 |
| Agent 自动调用 | 允许 |

查询结果只包含当前任务所需信息，不返回其他用户数据。

### 4.2 `get_recent_progress`

| 项目 | 内容 |
|---|---|
| 功能 | 读取最近一段时间的跟进和任务进度 |
| 风险等级 | `R0` |
| 输入 | `plan_id`、开始时间、结束时间、可选任务 ID |
| 前置条件 | 当前用户拥有计划 |
| 权限 | 只读 |
| 副作用 | 无 |
| 输出 | `CheckIn`、`TaskUpdate`、任务当前状态和阻碍 |
| 幂等策略 | 天然幂等 |
| 失败行为 | 时间范围非法时拒绝 |
| Agent 自动调用 | 允许 |

### 4.3 `get_preference_context`

| 项目 | 内容 |
|---|---|
| 功能 | 读取已确认画像事实和通知偏好 |
| 风险等级 | `R0` |
| 输入 | 需要的偏好类别 |
| 前置条件 | 当前用户已登录 |
| 权限 | 只读 |
| 副作用 | 无 |
| 输出 | 已确认 `ProfileFact`、时区、免打扰时段和通知渠道 |
| 幂等策略 | 天然幂等 |
| 失败行为 | 类别不支持时返回参数错误 |
| Agent 自动调用 | 允许 |

该工具不能返回未确认的 `ProfileInsight`、被删除事实或敏感内部审计数据。

### 4.4 `get_weekly_evidence`

| 项目 | 内容 |
|---|---|
| 功能 | 获取指定周期复盘所需的业务证据 |
| 风险等级 | `R0` |
| 输入 | `plan_id`、周期开始和结束时间 |
| 前置条件 | 当前用户拥有计划，时间范围明确 |
| 权限 | 只读 |
| 副作用 | 无 |
| 输出 | 周期内生效的计划版本、任务快照、`CheckIn` 和 `TaskUpdate` |
| 幂等策略 | 天然幂等 |
| 失败行为 | 范围过大、权限不符或数据不完整时明确报错 |
| Agent 自动调用 | 允许 |

### 4.5 `web_search`

| 项目 | 内容 |
|---|---|
| 功能 | 搜索公开资料 |
| 风险等级 | `R0` |
| 输入 | 查询词、最大结果数、可选时效要求 |
| 前置条件 | 当前用户已登录且未超过搜索频率 |
| 权限 | 只读外部资料 |
| 副作用 | 保存搜索结果引用 |
| 输出 | `Source`：标题、URL、摘要、引用片段、获取时间 |
| 幂等策略 | 可缓存，重复调用不产生业务副作用 |
| 失败行为 | 返回明确搜索失败，不生成来源 |
| Agent 自动调用 | 允许 |

Agent 只能使用搜索供应商返回的结果，不能自行访问任意 URL，也不能声称使用未返回的链接。

## 5. 草稿工具

### 5.1 `create_plan_draft`

| 项目 | 内容 |
|---|---|
| 功能 | 为目标生成计划草稿 |
| 风险等级 | `R1` |
| 输入 | `goal_id`、已确认上下文快照、阶段、里程碑、任务和依赖结构 |
| 前置条件 | 当前用户拥有目标，结构通过 Schema 和业务校验 |
| 权限 | 创建草稿 |
| 副作用 | 创建或更新 `Plan DRAFT` 和 `PlanVersion DRAFT` |
| 幂等策略 | 使用请求幂等键；同一次请求不重复创建草稿 |
| 失败行为 | 结构不合法时不创建任何部分记录 |
| Agent 自动调用 | 允许 |

该工具不能激活计划，不能创建跟进安排，也不能把计划设置为 `ACTIVE`。

### 5.2 `update_plan_draft`

| 项目 | 内容 |
|---|---|
| 功能 | 修改尚未生效的计划草稿 |
| 风险等级 | `R1` |
| 输入 | 草稿版本 ID、修改内容和预期修订号 |
| 前置条件 | 计划仍为 `DRAFT`，用户拥有计划 |
| 权限 | 修改自己的草稿 |
| 副作用 | 修改草稿结构 |
| 幂等策略 | 使用内容版本或请求幂等键 |
| 失败行为 | 计划已生效或版本已过期时拒绝 |
| Agent 自动调用 | 允许 |

### 5.3 `propose_plan_change`

| 项目 | 内容 |
|---|---|
| 功能 | 为生效计划提出结构变更建议 |
| 风险等级 | `R1`（只产生待审批记录） |
| 输入 | `plan_id`、`base_version_id`、修改前后差异、理由、证据 |
| 前置条件 | 当前版本仍有效，差异可结构化计算 |
| 权限 | 用户或 Agent 可提出 |
| 副作用 | 创建 `PlanChangeProposal PENDING_APPROVAL` |
| 幂等策略 | 相同基准版本和相同差异返回原建议 |
| 失败行为 | 基准版本过期时拒绝或标记 `EXPIRED` |
| Agent 自动调用 | 允许 |

风险等级由后端根据实际差异重新计算，不能信任 LLM 自报的风险等级。该工具不能执行批准或应用。

### 5.4 `generate_weekly_review`

| 项目 | 内容 |
|---|---|
| 功能 | 根据周期证据生成结构化复盘 |
| 风险等级 | `R1` |
| 输入 | `plan_id`、周期、计划版本和证据引用 |
| 前置条件 | 当前用户拥有计划，时间范围明确 |
| 权限 | 创建复盘 |
| 副作用 | 创建 `Review GENERATING`，完成后进入 `READY` 或 `FAILED` |
| 幂等策略 | 同一计划、同一周期和证据版本只生成一次，除非用户明确要求重新生成 |
| 失败行为 | 失败时保存原因，不修改任务和画像 |
| Agent 自动调用 | 允许 |

该工具可以提出下一阶段建议，但不能直接修改计划。

### 5.5 `propose_profile_insight`

| 项目 | 内容 |
|---|---|
| 功能 | 根据真实历史提出候选画像规律 |
| 风险等级 | `R1` |
| 输入 | 个性化维度、结构化结论、适用范围、支持证据 ID、矛盾证据 ID |
| 前置条件 | 证据属于当前用户，且不是敏感身份或人格诊断 |
| 权限 | Agent 或系统提出 |
| 副作用 | 创建或更新 `ProfileInsight CANDIDATE` |
| 幂等策略 | 按用户、维度、结论和证据集合去重 |
| 失败行为 | 证据不存在或不属于当前用户时拒绝 |
| Agent 自动调用 | 允许 |

该工具不能确认洞察，也不能创建正式 `ProfileFact`。证据评分由确定性评分服务完成。

### 5.6 `propose_profile_fact`

| 项目 | 内容 |
|---|---|
| 功能 | 从模糊对话中提出待确认画像信息 |
| 风险等级 | `R1` |
| 输入 | 信息类别、键值、原始消息引用和适用条件 |
| 前置条件 | 原始消息属于当前用户且能够定位 |
| 权限 | Agent 提出建议 |
| 副作用 | 创建 `ProfileFact PENDING_CONFIRMATION` |
| 幂等策略 | 相同来源和相同值不重复创建 |
| 失败行为 | 无有效来源或与已拒绝内容相同时拒绝 |
| Agent 自动调用 | 允许 |

该工具不能创建敏感推断，也不能把待确认信息直接放进当前画像。

## 6. 操作工具

### 6.1 `record_task_progress`

| 项目 | 内容 |
|---|---|
| 功能 | 根据用户明确反馈记录任务状态和进度 |
| 风险等级 | `R2` |
| 输入 | `plan_id`、用户反馈来源、一个或多个任务更新 |
| 前置条件 | 计划允许更新；任务属于该计划和用户；存在明确用户反馈 |
| 权限 | 记录当前用户反馈 |
| 副作用 | 创建 `CheckIn` 和 `TaskUpdate`，更新任务状态，重算里程碑和进度 |
| 幂等策略 | `idempotency_key` 唯一；同一用户消息重复处理只产生一次更新 |
| 失败行为 | 任一任务校验失败时整个请求回滚 |
| Agent 自动调用 | 允许，但必须有明确用户输入作为依据 |

不允许根据模糊情绪、推测或模型想象更新任务。

### 6.2 `reschedule_next_check_in`

| 项目 | 内容 |
|---|---|
| 功能 | 修改下一次跟进时间 |
| 风险等级 | `R2` |
| 输入 | `schedule_id`、新时间、用户时区、调整原因 |
| 前置条件 | 当前用户拥有安排，计划有效，新时间不在被禁止时段 |
| 权限 | 执行低风险提醒调整 |
| 副作用 | 更新 `next_due_at`，不改变跟进安排状态 |
| 幂等策略 | 以安排 ID、新时间和请求键保证幂等 |
| 失败行为 | 时间不合法或安排已取消时拒绝 |
| Agent 自动调用 | 允许 |

### 6.3 `apply_low_risk_plan_adjustment`

| 项目 | 内容 |
|---|---|
| 功能 | 自动应用不改变关键约束的计划调整 |
| 风险等级 | `R2` |
| 输入 | `plan_id`、`base_version_id`、结构化调整、原因和证据 |
| 前置条件 | 计划为 `ACTIVE`，调整满足全部低风险条件 |
| 权限 | 系统或 Agent 执行允许的自动调整 |
| 副作用 | 创建新 `PlanVersion` 并原子替换旧版本 |
| 幂等策略 | 基于基准版本、调整内容和幂等键去重 |
| 失败行为 | 不满足低风险条件时拒绝，并建议创建关键变更 Proposal |
| Agent 自动调用 | 允许，但必须由后端重新分类 |

### 6.4 `schedule_check_in`

| 项目 | 内容 |
|---|---|
| 功能 | 为生效计划创建跟进安排 |

| 前置条件 | 计划已生效，用户已设置或接受提醒偏好 |
| 权限 | 创建允许的提醒 |
| 副作用 | 创建 `FollowUpSchedule ACTIVE` |
| 幂等策略 | 一个计划、一个跟进规则和一次请求只创建一项安排 |
| 失败行为 | 计划未生效、渠道不支持或频率非法时拒绝 |
| Agent 自动调用 | 允许 |

### 6.5 `save_notification_preference`

| 项目 | 内容 |
|---|---|
| 功能 | 保存用户明确选择的提醒渠道和时段 |
| 风险等级 | `R2` |
| 输入 | 渠道、时段、时区、免打扰时间和选择来源 |
| 前置条件 | 用户明确选择，配置合法 |
| 权限 | 更新自己的通知偏好 |
| 副作用 | 更新后续跟进和通知目标 |
| 幂等策略 | 相同配置重复提交返回同一结果 |
| 失败行为 | 未验证的渠道或非法时段拒绝 |
| Agent 自动调用 | 允许，但必须基于用户明确选择 |

## 7. 风险等级

| 等级 | 含义 | 默认行为 |
|---|---|---|
| `R0` | 只读查询 | 可直接执行 |
| `R1` | 创建草稿或待确认记录 | 可直接执行，但对象不能直接生效 |
| `R2` | 低风险、可审计、可修正的当前执行调整 | 校验后自动执行 |
| `R3` | 改变计划约束、范围或关键结构 | 只能提出，必须用户确认 |
| `R4` | 身份、安全、删除和最终审批 | Agent 无权直接调用 |

如果后端无法判断一个操作是否满足低风险条件，必须升级为 `R3` 或更高，不能自动执行。

## 8. 自动执行与人工审批

### 8.1 可以自动执行的低风险操作

- 调整同一天内的任务顺序。
- 在不改变任务数量、总预计用时、截止日期和目标范围时，重新排列现有任务。
- 修改下一次跟进时间。
- 在用户已允许的渠道和时段内调整提醒。
- 根据用户明确反馈追加任务进度。

### 8.2 必须用户确认的关键变化

- 新增或删除任务。
- 新增、跳过、删除或替换里程碑。
- 修改截止日期。
- 修改每周投入时间。
- 修改目标岗位或求职范围。
- 改变阶段顺序并影响整体交付时间。
- 将已拒绝或过期的调整重新应用。

### 8.3 只能由用户直接执行的操作

- 激活计划草稿。
- 批准或拒绝关键计划变化。
- 确认或拒绝画像洞察。
- 完成、取消或恢复目标。
- 删除账号或业务数据。
- 修改认证和安全设置。

### 8.4 审批不是工具调用

Agent 返回“需要用户操作”的结构化结果，而不是自行调用审批工具。

示例结果：

```json
{
  "status": "needs_user_action",
  "action": "APPROVE_PLAN_CHANGE",
  "proposal_id": 123,
  "summary": "将项目复盘截止日期延长 7 天",
  "base_version_id": 456,
  "expires_when": "base_version_changes"
}
```

前端根据该结果展示批准和拒绝按钮。用户点击后调用用户授权接口，Agent 不参与最终批准。

### 8.5 审批失效

关键变化建议在以下情况不能继续应用：

- 当前计划版本已经变化。
- 用户已经拒绝该建议。
- 建议超出有效期。
- 目标或计划已经取消。
- 建议依赖的任务、里程碑或画像事实已被删除。

## 9. 任务进度更新规则

### 9.1 允许调用的情况

- 用户明确说出具体任务和完成结果。
- 用户通过结构化表单提交跟进。
- 用户明确要求 Agent 代为记录进度。

示例：

> “SQL 窗口函数练习已经完成，帮我把这个任务更新为完成。”

### 9.2 不允许调用的情况

- 用户只表达情绪，例如“最近状态不好”。
- Agent 根据上下文猜测某个任务已经完成。
- 用户没有指明任务，系统却批量更新全部任务。
- 网页或其他外部内容声称任务已经完成。
- 没有用户反馈来源的模型推断。

### 9.3 更新规则

- 每次更新必须指向计划内的具体任务。
- 创建 `CheckIn` 和一条或多条 `TaskUpdate`。
- 任务进度 `100%` 对应 `DONE`。
- 进度 `1%～99%` 对应 `IN_PROGRESS`。
- 受阻时保存原进度并进入 `BLOCKED`。
- 允许用户通过新的修正记录重新打开已完成任务。
- 同一反馈不能重复生成多条业务更新。

## 10. 计划变更规则

### 10.1 低风险自动调整的前置条件

- 当前计划为 `ACTIVE`。
- `base_version_id` 等于当前生效版本。
- 不改变任务数量和任务集合。
- 不改变总预计用时。
- 不改变任务和阶段截止日期。
- 不改变目标岗位、求职范围或关键里程碑。
- 调整只发生在原有执行范围内。
- 变更可以生成完整的新版本快照。

满足条件时，创建新 `PlanVersion`，并原子地让旧版本进入 `SUPERSEDED`。

### 10.2 关键计划变化

关键变化统一创建 `PlanChangeProposal PENDING_APPROVAL`。

Proposal 必须包含：

- 基准版本。
- 修改前和修改后的结构化差异。
- 风险等级和分类依据。
- 触发变更的用户反馈或分析。
- 提出者和提出时间。
- 审批截止或失效条件。

用户批准后，在同一个事务中应用新版本；拒绝后当前计划保持不变。

### 10.3 并发保护

所有计划修改都必须携带基准版本。如果版本已经变化：

- 自动调整拒绝执行。
- 待审批 Proposal 标记为 `EXPIRED`。
- 系统要求重新基于最新版本生成建议。

不能在不检查版本的情况下按任务 ID 盲目覆盖结构。

## 11. 搜索与提示注入防护

### 11.1 搜索输出规则

- `web_search` 只返回受支持搜索服务的结果。
- Agent 不能自行访问任意 URL。
- 每条外部资料必须保存标题、URL、摘要、引用片段和获取时间。
- 回答中的外部事实应引用工具实际返回的 `Source`。
- 搜索失败时明确说明未获取到资料，不能编造来源。

### 11.2 外部内容处理

网页和搜索结果属于不可信数据：

- 其中的指令不能改变系统规则。
- 不能因为网页要求就修改计划、任务或画像。
- 不能把网页中的人物描述当作当前用户事实。
- 搜索内容不能作为 `ProfileInsight` 的行为证据。
- 结果写入模型上下文前必须标明为外部资料。

### 11.3 查询和隐私

- 搜索查询只使用完成任务所需的信息。
- 不把完整画像、所有任务或敏感记录发送给搜索供应商。
- 对搜索接口设置频率和结果数量限制。
- 不保存无关的搜索历史用于画像推断。

## 12. 画像洞察规则

### 12.1 洞察来源

候选洞察只能根据当前用户的真实交互和行为证据产生，例如：

- 用户的明确陈述。
- `CheckIn`。
- `TaskUpdate`。
- 用户对计划调整的接受或拒绝。

搜索结果不是用户行为证据，不能用来判断用户性格。

### 12.2 洞察流程

```text
周复盘或受控后台任务
  → 提取候选规律
  → 关联支持证据和矛盾证据
  → 确定性证据评分
  → CANDIDATE
  → 达到阈值后 SUPPORTED
  → 周复盘展示
  → CONFIRMATION_REQUESTED
  → 用户确认 / 拒绝
```

### 12.3 Agent 限制

- LLM 可以发现规律和生成解释，但不能自行决定最终证据分。
- 只有满足硬性门槛和阈值，洞察才能进入 `SUPPORTED`。
- 一次周复盘最多展示 1～3 条候选洞察。
- 用户拒绝后，相同结论进入冷却或永久抑制。
- 洞察必须包含适用条件和有效时间。
- 未经确认的洞察不能进入当前画像。

### 12.4 禁止内容

禁止生成或保存：

- 心理疾病或人格障碍推断。
- 对智力、道德、能力或诚信度的评价。
- 敏感身份推断。
- 没有证据的用户刻板标签。
- 通过失败次数推断“用户懒散”或“没有毅力”。
- 用户明确拒绝后更换措辞继续推荐相同结论。

## 13. Agent 工作流

### 13.1 标准执行流程

```text
1. 认证并确定当前用户
2. 加载最小必要上下文
3. 识别用户意图和风险等级
4. LLM 生成结构化工具调用
5. 校验 Schema、权限、状态和基准版本
6. 查询或草稿操作直接执行
7. 低风险操作执行并记录版本
8. 关键操作创建待确认 Proposal
9. 记录 AgentRun 和 ToolCall
10. 返回真实结果和下一步用户操作
```

### 13.2 工具执行约束

- 单次 Agent 运行的最大工具调用次数必须受限。
- 每次工具调用必须有超时。
- 工具不能无限递归调用自身。
- 有依赖关系的工具按顺序执行。
- 写操作失败时不能继续报告成功。
- 用户看到的最终结果必须来自工具真实返回值。
- Agent 不能因为模型认为数据存在就跳过查询。

### 13.3 上下文最小化

上下文构建器只加载当前任务所需信息：

- 当前用户和目标。
- 当前生效计划版本。
- 相关任务和最近证据。
- 已确认的画像事实。
- 与本次请求相关的通知偏好。

不得把其他用户数据、完整审计日志、密钥或不相关敏感信息放入模型上下文。

## 14. 并发、幂等和失败恢复

### 14.1 幂等

所有写工具必须携带 `idempotency_key`。以下操作尤其需要幂等：

- 记录任务进度。
- 创建或调整跟进安排。
- 应用计划变更。
- 生成通知。
- 创建画像事实。
- 生成周复盘。

同一幂等键重复调用时，应返回第一次成功结果，不能创建重复业务记录。

### 14.2 事务

- 一个工具调用的业务写入应在同一事务中完成。
- 计划版本切换、旧版本替代和 Proposal 更新必须原子完成。
- 任务更新、进度重算和里程碑更新必须保持一致。
- 事务失败时回到调用前状态。

### 14.3 超时和重试

- 只读查询可以按策略重试。
- 写操作只允许在幂等条件下重试。
- 参数错误、权限错误和状态冲突不能自动重试。
- 模型超时不能留下未完成业务写入。
- 搜索失败不能生成虚构引用。
- 通知发送失败按渠道策略重试，并保留每次投递记录。

### 14.4 错误返回

工具应返回稳定错误码，例如：

- `UNAUTHORIZED`
- `RESOURCE_NOT_FOUND`
- `VERSION_CONFLICT`
- `INVALID_STATE`
- `INVALID_ARGUMENT`
- `RATE_LIMITED`
- `UPSTREAM_FAILED`
- `CONFIRMATION_REQUIRED`

Agent 不能把工具错误改写成“操作成功”。

### 14.5 审计

每次 `AgentRun` 和 `ToolCall` 至少记录：

- 当前用户和关联会话。
- 工具名称和风险等级。
- 经过校验的参数摘要。
- 调用时间和耗时。
- 成功、失败或待确认结果。
- 错误码和重试次数。
- 关联对象 ID。

日志中不能保存密码、完整令牌、API Key 或不必要的敏感正文。

## 15. 工具调用验收场景

以下场景应在后续测试中覆盖。

### 15.1 权限

1. Agent 不能读取其他用户的计划和任务。
2. 模型传入伪造 `user_id` 时，后端忽略并拒绝越权操作。
3. 搜索和任务更新不能跨用户混用上下文。

### 15.2 任务进度

1. 用户明确说“项目复盘完成 50%”时，生成 `CheckIn` 和对应 `TaskUpdate`。
2. 用户只说“最近不太好”时，Agent 不得批量修改任务。
3. 相同用户消息被重复处理时，只生成一次任务更新。
4. 任一任务不属于当前计划时，整个进度更新回滚。

### 15.3 计划变更

1. 调整同日任务顺序可以自动产生新版本。
2. 延长截止日期不能自动执行，只能创建 Proposal。
3. 用户拒绝 Proposal 后计划版本不变。
4. 基准版本已过期时，自动调整失败，旧 Proposal 进入 `EXPIRED`。
5. 批准变更与应用版本必须原子完成。

### 15.4 搜索

1. 搜索内容要求 Agent 忽略系统规则时，仍然不能修改计划。
2. 搜索失败时回答不得包含虚构来源。
3. 回答中使用外部事实时能够引用真实 `Source`。
4. 搜索结果不能成为用户画像的行为证据。

### 15.5 画像洞察

1. 少于 3 条支持证据的洞察不能进入 `SUPPORTED`。
2. LLM 自报的置信度不能代替确定性证据分。
3. 用户确认后才创建正式 `ProfileFact`。
4. 用户拒绝后，相同洞察不能立即重复询问。
5. 未确认洞察不能出现在当前用户画像中。

### 15.6 通知和失败恢复

1. 计划暂停后不再创建新的有效提醒。
2. 重复发送请求不会产生多个逻辑通知。
3. Worker 崩溃后可以从安全状态恢复。
4. 工具超时不能留下部分写入。
5. 任何失败结果都必须能被用户和后台观察到。
