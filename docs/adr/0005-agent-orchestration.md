# ADR-005：使用自定义状态机和受控工具编排 Agent

- 状态：Accepted
- 日期：2026-11-22
- 决策者：项目所有者

## 背景

Agent 需要生成计划、搜索资料、跟进任务、提出计划调整和生成周复盘。LLM 输出不确定，而关键业务操作必须可验证、可审计并遵守用户审批。

## 决策

采用自定义后端工作流状态机与 LLM function calling。

```text
识别意图
  → 加载最小必要上下文
  → 生成结构化工具调用
  → 校验 Schema、权限和状态
  → 查询或草稿操作
  → 风险分类
  → 自动执行或请求用户确认
  → 记录 AgentRun / ToolCall
  → 返回真实结果
```

LLM 通过 `LLMProvider` 抽象调用，初始供应商为 DeepSeek 的 OpenAI 兼容接口。

## 关键规则

1. LLM 不持有数据库连接，不执行 SQL。
2. 工具由后端白名单注册和校验。
3. Agent 不能调用用户专属审批接口。
4. 模型输出必须经过 Pydantic 校验。
5. 工具参数不能包含可信的 `user_id`，身份由服务端注入。
6. 低风险调整和关键变化使用不同工具。
7. 画像洞察评分由确定性服务计算，不使用 LLM 自报置信度。
8. 工具调用保存幂等键、结果、错误、耗时和关联业务对象。
9. Agent 对话使用持久化运行记录和 SSE 事件流。

## 备选方案

### LangGraph 作为核心编排

适合复杂图和多 Agent，但当前流程仍可由明确状态机表达。过早引入框架会把数据库、工具和提示词与框架生命周期绑定。

### 一次性提示词生成全部结果

实现简单，但无法可靠执行工具、保证权限或产生可审计的业务结果。

### 完全自主 Agent

不符合关键变化必须由用户确认的产品要求，也难以稳定测试和解释。

## 后果和代价

- 需要自行维护工具注册、工作流状态和执行审计。
- 比依赖完整 Agent 框架多一些编排代码。
- 流程更可控、可测试，失败后更容易恢复。
- 以后可以在 `agent` 模块内部引入图编排，不改变 API 和领域模型。

## 验证方式

- 使用假 LLM 可以测试全部工具和状态转换。
- 搜索结果中的提示注入不能触发计划修改。
- 工具失败不会产生虚假成功。
- 关键变化一定进入 `PlanChangeProposal`。
- 画像洞察必须由用户确认后才能进入正式画像。
