# ADR-004：使用邮箱密码、JWT 与安全 Cookie 认证

- 状态：Accepted
- 日期：2026-11-22
- 决策者：项目所有者

## 背景

MyJARVIS 需要多用户注册登录，用户只能访问自己的画像、目标、计划和执行记录。第一载体是同域名 PWA，未来可能封装为 Capacitor App 或接入飞书 OAuth。

## 决策

MVP 认证方案：

- 邮箱作为主要登录标识。
- 密码使用 Argon2id 哈希。
- 短期访问令牌和可轮换刷新令牌。
- 同域 PWA 使用 `Secure`、`HttpOnly` Cookie。
- 对 Cookie 认证的写请求增加 CSRF 防护。
- 刷新令牌在服务端保存哈希和会话状态，支持注销与撤销。
- 认证适配层隔离 PWA、未来 Capacitor 和飞书 OAuth。

## 选择理由

- 不把长期令牌放在前端 localStorage，减少 XSS 导致持久凭证泄漏的风险。
- 同域 PWA 与后端共享安全 Cookie，部署和刷新流程更简单。
- 服务端会话可以支持多设备注销和异常会话撤销。
- Argon2id 是当前推荐的密码哈希方案。
- 适配层可以避免未来移动 App 或第三方登录导致认证逻辑重写。

## 备选方案

### 只在 localStorage 保存 JWT

接入简单，但长期令牌对 XSS 更敏感，不建议作为长期方案。

### 服务端传统 Session

安全可靠，但未来 Capacitor 和第三方 OAuth 的适配需要额外设计。

### 手机验证码

需要短信供应商、成本和防滥用系统，不适合作为 MVP 第一认证方式。

### 飞书 OAuth

适合企业租户，但不是所有潜在用户都有飞书身份，因此作为后续扩展入口。

## 安全要求

1. 密码不得记录在日志中。
2. 刷新令牌必须可轮换并支持服务端撤销。
3. 登录、刷新和密码相关接口需要限流。
4. Cookie 写请求必须防 CSRF。
5. 认证失败不能泄漏可用于账号枚举的信息。
6. 所有业务资源的用户归属校验不能只依赖前端。
7. Agent 身份始终来自服务端认证上下文，不能使用模型传入的用户 ID。

## 后果和代价

- Cookie、CSRF 和跨域配置需要仔细测试。
- 未来 Capacitor 可能需要同时支持 Bearer token 适配。
- 需要维护刷新令牌和会话表。

## 验证方式

- 用户无法访问其他用户数据。
- 注销后刷新令牌立即失效。
- 密码和令牌不会出现在日志中。
- 登录失败限流生效。
- PWA 与未来移动端适配不会复制领域权限逻辑。

## 后续待办

- 在 P3 实现认证表、令牌轮换和 CSRF。
- 在部署阶段配置 HTTPS 和安全 Cookie。
- 飞书 OAuth 通过独立 ADR 和 adapter 扩展。
